## 整体架构概览

### 系统分层架构

```
┌─────────────────────────────────────────────────┐
│          业务接入层 (API Gateway)                │
│  - 订单服务API  - 账单查询API  - 计量上报API    │
└─────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────┐
│               核心业务层                         │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐        │
│  │订单服务  │ │账单服务  │ │计量服务  │        │
│  │Order Svc │ │Bill Svc  │ │Meter Svc │        │
│  └──────────┘ └──────────┘ └──────────┘        │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐        │
│  │定价服务  │ │支付服务  │ │结算服务  │        │
│  │Price Svc │ │Pay Svc   │ │Settle Svc│        │
│  └──────────┘ └──────────┘ └──────────┘        │
└─────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────┐
│               数据存储层                         │
│  ┌──────────────┐      ┌──────────────┐        │
│  │    MySQL     │      │  ClickHouse  │        │
│  │ 业务数据     │      │  计量&账单    │        │
│  │ 订单/用户/   │      │  海量明细     │        │
│  │ 定价规则     │      │  OLAP分析     │        │
│  └──────────────┘      └──────────────┘        │
│  ┌──────────────┐      ┌──────────────┐        │
│  │    Redis     │      │    Kafka     │        │
│  │ 缓存/计数器  │      │  消息队列     │        │
│  └──────────────┘      └──────────────┘        │
└─────────────────────────────────────────────────┘
```

### 核心设计原则

1. **服务职责分离**: 订单、计量、账单、定价、支付各自独立,通过事件和API协作
2. **存储分离**: 业务数据(MySQL)与海量分析数据(ClickHouse)分离
3. **异步解耦**: 计量数据通过 Kafka 异步写入,避免阻塞业务流程
4. **可插拔扩展**: 新产品类型通过配置定价规则接入,无需改代码

## 服务职责说明

| 服务 | 职责 | 关键能力 |
|------|------|---------|
| **订单服务** | 处理用户购买行为 | 创建订单、订单状态流转、订单查询 |
| **计量服务** | 采集和聚合资源使用数据 | 实时计量上报、秒级数据聚合、计量查询 |
| **账单服务** | 生成和管理账单 | 按小时出账、红冲账单、账单查询 |
| **定价服务** | 管理价格策略 | 价格计算、折扣规则、资源包配置 |
| **支付服务** | 处理支付和退款 | 在线支付、余额扣减、原路退款 |
| **结算服务** | 企业级结算 | 月结对账、授信管理、发票管理 |

## 数据流转架构

### 计量数据流

```
资源实例 → 计量Agent → Kafka → 计量服务 → ClickHouse
                                          ↓
                                    小时聚合(物化视图)
                                          ↓
                                    账单服务 → MySQL
```

### 订单流程

```
用户下单 → 订单服务 → 定价服务 → 生成订单
                               ↓
                          账单服务 → 生成账单
                               ↓
                          支付服务 → 扣减余额
                               ↓
                          资源管理 → 开通资源
```

## 技术选型

### 后端技术栈

- **语言**: Go 1.25
- **Web框架**: Gin/Echo
- **ORM**: GORM
- **微服务**: gRPC + Protobuf
- **配置中心**: Viper + Consul
- **服务注册**: Consul/Etcd

### 数据存储

- **关系数据库**: MySQL 8.0 (主从架构)
- **列式数据库**: ClickHouse 23.x (分布式集群)
- **缓存**: Redis 7.x (哨兵/集群模式)
- **消息队列**: Kafka 3.x (多副本)

### 基础设施

- **容器化**: Docker + Kubernetes
- **监控**: Prometheus + Grafana
- **日志**: ELK Stack (Elasticsearch + Logstash + Kibana)
- **追踪**: Jaeger (分布式追踪)
- **网关**: Nginx/Kong

### 高可用设计

1. **服务高可用**: 多实例部署 + 健康检查 + 自动重启
2. **数据库高可用**: MySQL 主从 + ClickHouse 副本
3. **Redis 高可用**: 哨兵模式 / 集群模式
4. **Kafka 高可用**: 多副本 + ISR 机制

## 扩展性设计

### 水平扩展

- **无状态服务**: 订单、账单、支付服务可任意扩展
- **有状态服务**: 计量服务通过 Kafka 分区扩展
- **数据库扩展**: MySQL 分库分表, ClickHouse 分布式表

### 垂直扩展

- **缓存优化**: Redis 缓存热点数据(定价规则、汇率)
- **读写分离**: MySQL 主库写、从库读
- **异步化**: 非核心流程异步处理(通知、日志)

## 安全设计

### 认证授权

- **API 认证**: JWT Token
- **服务间认证**: mTLS
- **权限管理**: RBAC (角色-权限-资源)

### 数据安全

- **敏感数据加密**: 身份证、手机号加密存储
- **传输加密**: HTTPS/TLS
- **SQL 注入防护**: 参数化查询
- **XSS/CSRF 防护**: 框架内置防护

## 监控告警

### 监控指标

- **服务指标**: QPS、延迟、错误率
- **业务指标**: 订单量、账单量、支付成功率
- **系统指标**: CPU、内存、磁盘、网络

### 告警策略

- **P0 告警**: 服务不可用、数据库宕机
- **P1 告警**: 错误率超阈值、支付失败
- **P2 告警**: 慢查询、磁盘空间不足
