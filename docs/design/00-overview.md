# Happy Billing 系统概述

**文档版本**: v1.0
**设计日期**: 2026-01-17
**设计目标**: 为 AI 云 PaaS 平台设计高可扩展、易接入、可插拔的订单账单模型

---

## 业务背景

Happy Billing 是一个专为 AI 云 PaaS 平台设计的企业级订单账单系统,支持 GPU 算力、存储、LLM Token 等多种产品类型的计费计量。

### 核心价值

- **高可扩展性**: 支持新产品类型快速接入,无需修改核心代码
- **易接入**: 提供标准化的计量上报和定价配置接口
- **可插拔**: 定价规则、支付方式、结算模式均支持灵活配置

---

## 核心业务特征

### 产品类型

- **GPU 算力**: 按小时/秒计费的 GPU 资源
- **存储服务**: 块存储、对象存储等
- **LLM Token**: 大语言模型 API 调用计费

### 计费模式

- **预付费** (包年包月): 先支付后使用,适用于稳定需求
- **后付费** (按量计费): 先使用后结算,适用于弹性需求
- **混合模式**: 支持同一租户同时使用两种模式

### 计费粒度

- **计量粒度**: 秒级数据采集
- **出账粒度**: 按小时汇总生成账单
- **结算粒度**: 实时结算或月度结算

### 定价模型

支持完整的价格体系:

- **固定价格**: 统一单价
- **阶梯价格**: 用量越大单价越低
- **时段价格**: 峰谷分时定价
- **资源包**: 预购买优惠包
- **折扣规则**: 用户级折扣、促销折扣

### 租户架构

完整的多租户体系:

```
Tenant (租户)
  └─ Organization (组织)
       └─ Project (项目/成本中心)
            └─ User (用户)
```

### 结算方式

企业级结算支持:

- **在线支付**: 支付宝、微信等
- **账户余额**: 预充值余额扣减
- **月结**: 企业客户月度对账
- **授信**: 信用额度管理

### 技术栈

- **应用框架**: Go 1.25 + Gin/Echo
- **业务数据库**: MySQL 8.0 (订单、账单、用户)
- **计量数据库**: ClickHouse (海量时序数据)
- **缓存**: Redis (定价规则、汇率、会话)
- **消息队列**: Kafka (事件驱动)

## 业务规则

### 预付费规则

1. **包年包月**: 下单即生成账单,立即支付
2. **服务期内不再出账**: 已预付整个服务期费用
3. **支持中途退款**: 按剩余时长比例退款

### 后付费规则

1. **按量计费**: 每小时生成账单汇总
2. **自动结算**: 从账户余额自动扣减
3. **余额不足**: 发送通知,可能停服

### LLM Token 计费规则

1. **记录每次调用明细**: 输入 token 和输出 token 分别计价
2. **按小时汇总出账**: 避免账单表数据爆炸
3. **支持追溯**: ClickHouse 中保留原始调用记录

### 退款机制

1. **原路退款**: 原支付方式退回
2. **红冲账单**: 生成负数账单记录
3. **退款审核**: 支持人工审核流程

## 系统特点

### 双存储架构

- **MySQL**: 存储业务数据 (订单、账单、用户),支持事务
- **ClickHouse**: 存储计量明细 (秒级数据),支持 OLAP 分析

### 双主键设计

- **物理主键**: id (BIGINT 自增),数据库内部使用
- **业务主键**: xxx_id (VARCHAR),业务层使用,便于沟通

示例:
```sql
tenants:
  id = 1                    -- 物理主键
  tenant_id = 'T20240117001'  -- 业务主键
```

### 多币种支持

- **本位币**: CNY (人民币)
- **展示币种**: 支持 USD、EUR、JPY 等
- **汇率管理**: 每日更新,账单记录汇率快照

### 事件驱动架构

- **Kafka 事件总线**: 服务间异步解耦
- **事件类型**: 订单创建、支付成功、账单生成、余额变更
- **消费者**: 计量服务、通知服务、BI 分析

## 快速开始

### 前置条件

- Go 1.25+
- MySQL 8.0+
- ClickHouse 23.x+
- Redis 7.x+
- Kafka 3.x+

### 核心流程示例

#### 用户购买包年 GPU

```
1. 用户下单 → 创建订单 (PENDING)
2. 查询定价 → 计算金额
3. 生成账单 (UNPAID)
4. 用户支付 → 扣减余额
5. 更新订单和账单 (PAID)
6. 创建资源实例 (RUNNING)
```

#### 按量计费出账

```
1. GPU 实例运行 → 每秒上报计量数据 (ClickHouse)
2. 每小时整点 → 聚合上一小时数据
3. 生成账单 (UNPAID)
4. 自动从余额扣减 (PAID)
5. 余额不足 → 通知用户
```
